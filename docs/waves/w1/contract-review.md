# Wave 1a contract: the review and what was done with it

Two Opus reviewers (seams; safety, correctness and feasibility) read docs/waves/w1a-contract.md once; one Sonnet agent applied the findings.

## Verdicts

- Not yet. As written, the parallel build will not compile and test green on the first or second try. Two problems are blockers. First, the new `SpriteSource.find` default clashes with `SpriteBank.find`, and SpriteBank.kt has no owner. Second, step 1 of 5.1 draws the sky gradient over the whole stage, which breaks `SceneRendererParityTest`, and INTEGRATE may not touch that test. Several major gaps would also fail on INTEGRATE's own checks: the renderer is never told the theme, so the props cannot be drawn; the golden file is written into the temporary test copy; `lint-ui -Check` fails and nobody may update its baseline; `make_places.py --check` cannot run in CI without the downloads; and FIRE calls an `AppearanceTags.TILT` that APPEAR is never told to define. The rest of the seams line up with the real code: the HearthScene and SceneState callers, the Appearance fields, the `DebugRequest` additions with their `Setting` types, the four PetNote kinds, the sprite timing table against ART-PET, PET and the real `mascot.pxl`, the `SceneGeometry` defaults against today's constants, and the AppRoot and build.gradle.kts lines. Fix the items below, and they are all one-line changes to the contract text.
- Not ready to hand to the build agents yet, but every fix is a change to the contract text, not to its structure. I re-derived the science independently (NOAA sun, Meeus GMST and precession, the truncated lunar series, the projection) and most reference values match to the stated precision: GMST at J2000 and in Meeus 12.a/12.b; the four equinox/solstice longitudes; all six new and full moons (elongation within 0.01 deg); Sirius at Oslo 8.05/145.55, Vega at Istanbul 65.43/84.52, Arcturus at Sydney 35.31/16.80; the four culminations; sunrise and sunset in all six places (within 1 min); Tromso polar day and night giving null; the Istanbul equinox altitude sequence; Sirius landing at (53,47); moonPhase16 buckets; the hemisphere rule of the moon shape; the planet oppositions; the 24 eclipse dates. Three reference values are wrong. SkyProjectionTest centre and edge contradict the projection formula. The Diyarbakir sunGold day is wrong. P17's offset clock defeats the deep-night rule. The weather is properly dark: two independent guards (enabled=false and an empty contact), only WeatherEngine calls the transport, and no location is read. The one defect there is the log reason the proof expects. Data safety: Appearance keys are additive and AppearanceStore.update keeps edited stored values separate from pins. The real data risks are the migration rule (a race, and an ambiguity about which keys it writes) and a hold gesture that can stop Hermes while the user is scrolling. "Always night equals today" is proven only for the bare renderer: production passes a dithered horizon in NIGHT mode, against R3, and P01 cannot match build 32 because Home 2.0 changes the height, band, Pêt and fire. The status-bar polarity can never turn dark with the threshold as written. Feasibility: SCENE and HOME are each too big for one agent that cannot compile. LOOK cuts break tests that require a sprite to be present. The paper-hat effect behind the 'app' day list has no area that draws it.
