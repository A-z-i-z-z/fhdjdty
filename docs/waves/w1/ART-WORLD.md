## 3. Shared symbols I PROVIDE

### 3.1 Commands

`python tools/art/craft_art.py [--only fire|scene|seasons|sky|props|illustrations|appicon|pet] [--out DIR] [--check] [--selftest]` (`python3` on CI). Plain run writes every file and prints `Wrote <path> (<n> sprites)`; `--check` writes nothing and prints `ok <file>` or `DIFF <file>` for all generated files (the existing CI step `build.yml:57` covers the new ones without a change), exit 1 on any difference; `--selftest` (new, exit 0/1, under 5 s, no Pillow) proves the numbers of section 8 that need no JVM: hashes, role coverage, sizes, frame counts, margins, colour counts. `--only pet` and the plain/`--check` run call `python tools/art/pet_clips.py [--check] [--out DIR]` through `subprocess` with `sys.executable`, skip it with the line `pet_clips.py not present` when the file is missing, and combine the exit codes. The script starts with `sys.path.insert(0, HERE)` (python `-I` does not put its own folder on the path).
`python tools/art/contact_sheet.py [existing options] [--tint-file F.json]`: F is `{"<char>": "#RRGGBB"|"#AARRGGBB", ...}`; it replaces those palette colours of every sprite shown (preview only; SCENE's Kotlin table is the authority).
Determinism rules for new generator code (README, platform note): integers and the seeded `Rng` only (`x = (x * 1103515245 + 12345) & 0x7FFFFFFF; next(n) = (x >> 8) % n`, never the `random` module); a float compared with a threshold goes through `q(v) = round(v, 6)`; run `--check` on Windows and, if WSL exists, on Linux.

### 3.2 The index-role table (the contract with SCENE; also `SceneRoles.TABLE`)

Every palette char of the four scene files has one role. Each scene file carries, before its `palette` line, one comment line per palette char: `# role <char> <FAMILY> <step>` (the parser ignores `#` lines). Steps run from dark (0) to light. The baked colour is the reference moment named in the last column; SCENE's tint table is keyed by role and never by colour; unaltered baked colours reproduce today's night.

| Chars (step order) | Family (steps) | Used for | Baked at |
|---|---|---|---|
| `1 2 3 4` | FAR (4) | far ridge body, the existing ramp (`farRamp`) | night |
| `w V W` | SNOW (3) | snow shadow, mid, bright (ridge snow, winter ground, snowy pines) | night |
| `a A` | HILL (2) | near hills body, rim | night |
| `T` | PINE (1) | evergreen silhouettes (`#0E091A`) | night |
| `D` | CANOPY (1) | deciduous crowns in `scene_near`, same shape and same `#0E091A` as `T` | night |
| `h g G j` | GROUND (4) | meadow deep, mid, hilltop rim, soil clearing | night |
| `N l L` | GRASS (3) | grass deep, dark, lit | night |
| `P p` | FLOWER (2) | cup (gold `#F5B82E`), petal (cream `#FFF6C8`) | night, spring |
| `e E` | LEAF (2) | fallen leaves: `e #5E2F1B`, `E #A9561F` | autumn |
| `x s S` | STONE (3) | pebble base shadow, shadow, top | night |
| `f F` | FORE (2) | foreground grass silhouette, highlight | night |
| `d M m n` | MOON (4) | earthshine disc `d #2A2644`, terminator `M`, body `m`, bright rim `n` | night |
| `z y Y` | SUN (3) | rim and rays `z #FF9A3C`, body `y #FFC94A`, core `Y #FFF0A8` | sunrise |
| `K k c C` | CLOUD (4) | belly `K #1B1A2E`, shade `k #26253E`, mid `c #3C3A58`, top `C #5A5878` | night |
| `b B u i I J O Q r R` | PROP (1 each, step 0) | props and woodpile, baked in daylight: `b #5A3A24` `B #8A5A34` `u #D8C9A8` `i #2F3340` `I #5C6578` `J #9AA3B8` `O #1F4A3A` `Q #2F6B50` `r #2C5F8A` `R #5FA3CF` | day |
| `7 8 9 0` | GLOW (1 each, step 0) | emissive: `7 #3CF2C8` `8 #1FA88D` `9 #FF8A2A` `0 #FFD27A` | always |

What the tint table must be able to say (the art relies on it): spring = today for FLOWER, fresh green GRASS and CANOPY; summer = golden-green GRASS, other FLOWER hues; autumn = russet CANOPY, ochre GRASS, russet LEAF; winter = GROUND and HILL to snow white and shade, GRASS to straw, CANOPY to bare dark, STONE frosted; SNOW, MOON, SUN, CLOUD follow the moment; PROP is multiplied towards the sky colour by the ambient light (night about 0.55, day 1.0); GLOW is never changed. Within a family the steps must stay in luminance order for every moment and season (SCENE's test).

```kotlin
// app.ui.pixel.stage (SceneRoles.kt, pure)
enum class SceneFamily { FAR, SNOW, HILL, PINE, CANOPY, GROUND, GRASS, FLOWER, LEAF, STONE, FORE, MOON, SUN, CLOUD, PROP, GLOW }
data class SceneRole(val family: SceneFamily, val step: Int)
object SceneRoles {
    const val KEEP: Int = 0x00000001                                   // colourOf answer meaning "use the baked colour" (no palette colour has alpha 0 and this low bit)
    val TABLE: Map<Char, SceneRole>                                    // the table above, 52 chars
    fun of(char: Char): SceneRole?                                      // null for chars outside the table (fire, illustrations)
    fun stepCount(family: SceneFamily): Int                             // FAR 4, SNOW 3, HILL 2, PINE 1, CANOPY 1, GROUND 4, GRASS 3, FLOWER 2, LEAF 2, STONE 3, FORE 2, MOON 4, SUN 3, CLOUD 4, PROP 1, GLOW 1
    fun parseHeader(fileText: String): Map<Char, SceneRole>             // reads the "# role" lines; bad lines skipped, never throws
    fun recolor(sprite: Sprite, frame: Int, colourOf: (SceneRole) -> Int): IntArray   // ARGB pixels; the lambda runs once per palette entry (not per pixel); KEEP or no role keeps the baked ARGB
}
```
Behaviour: `recolor(s, f) { SceneRoles.KEEP }` equals `SpriteRaster.argb(s, f)` exactly.

Season rules for the generator (`SEASONS` dict; spring is today's code path, so it reproduces today's bytes):
- Far: `sh_eff = max(0, int(round(sh * snow_mul)) + snow_add)` replaces `sh` only in the snow tests (`dy < snow_edge`, `dy == snow_edge`), where `snow_edge = sh_eff + int(round(sin((x - px) * 0.55) * gully))`; rock shading keeps `sh`. (`snow_mul`, `snow_add`, `gully`): spring (1.0, 0, 1.6), summer (0.45, -1, 1.6), autumn (0.75, 0, 1.6), winter (1.9, 3, 2.2).
- Ground summer: spring's tufts plus 16 more from `Rng(41)` (x 6..170, ground rows 8..30, outside the clearing ellipse), and 6 flowers from `Rng(42)` instead of today's 5. Autumn: no flowers, 30 leaf clusters from `Rng(43)` (2 to 3 pixels `E`, one `e` below right). Winter: no flowers; snow over everything outside the clearing ellipse (`in_clearing >= 0.7`): `W` on the top line, `V` where `bayer(x, y) < 0.78` (rows 0 to 14) or `< 0.55` (below), `w` under a snow pixel whose lower neighbour is bare; tufts are 2 pixels tall; pebbles stay; the clearing around the fire stays bare soil `j`/`g` (it melts by the fire).
- Moon phases: disc centre (7.5, 7.5), radius 5.6; with `a = 2 pi k / 16`, `s = sqrt(1 - v^2)`, `xt = cos(a) * s`: waxing (k below 8) lit when `u >= xt`, waning (k above 8) lit when `u <= -xt` (u, v = pixel centre minus centre, divided by the radius); unlit disc pixels `d`; lit pixels `m`, `M` within 1 pixel of the terminator, `n` on the lit outer rim; lit pixels at (u, v) = (-0.3, -0.2), (0.25, 0.3), (0.1, -0.45) are `M` (maria).

## 10. Cost

Per frame (30 fps at most, 0 while Home is off screen): the art itself costs nothing; the consumers blit at most: sun 225 px, moon 225, clouds up to 3 sprites (about 4 000 px), props 1 700, woodpile 450, about 6 600 pixel operations, estimated 0.05 ms on the optimised build. SCENE must cache the tinted rasters per (sprite, frame, tint key): about 14 live rasters of at most 176 x 46 x 4 = 32 KB (under 0.5 MB), each rebuilt in about 50 microseconds (8 000 palette lookups, one lambda call per palette entry of at most 52). Rebuild only when the quantised moment bucket changes (a blend step of 1/48 changes at most every 30 s at dawn) and at most two per frame. Memory at rest: about 82 000 new pixel-frames x 8 bytes (indices and plain raster) = 0.65 MB. Start: the new files add about 100 KB of text (about 25 KB compressed) to the 180 KB of today, parsed by `SpriteBank.preload` on its own thread (a few milliseconds). APK: about 30 KB compressed against the plan's 1.5 MB share for art. Generator: `--check` and `--selftest` each under 5 s.

## 11. Risks, and where the plan or the design language does not fit the code

1. `SceneRendererParityTest` fails on any pixel change (`LegacyHearthReference`): the base sprites are protected by the hash test and the refactor must not reorder a `put`; `D` has the colour of `T`.
2. `SpriteLoader` skips a whole file on one bad row (`SpriteLoader.kt:15`, survey B): a mistake in `scene.pxl` would make the renderer's constructor throw. The generator therefore parses its own output with `pxl.parse` before writing and `--selftest` runs it; the new sprites live in new files so a new mistake cannot take the five base sprites with it (only `scene.pxl` is regenerated, with comments and `D`).
3. Design language 6.1 and 8.1 speak of a 180 x 160 framebuffer; the real stage is 144 to 176 wide and about 108 to 120 high (`StageGrid.forScene`, `StageGrid.kt:17`), `artX` is 0 to -16 (`SceneRenderer.kt:70`) and `ART_W` is a constant 176 (`SceneRenderer.kt:311`). All anchors are in art coordinates relative to `artX` and `g`; the collapsed strip and the bottom band of HOME's draft move `g` and `fbase`, so props are positioned from `g` only.
4. Design language section 9 says empty states use 24 x 24 sprites at "2u per pixel"; HOME asked for a 32 x 32 `empty_bubble` and `EmptyState` draws a 96 dp picture today (`EmptyState.kt:44`), which 32 px at 3 dp reproduces. I made all eight empties 32 x 32 and the tiles 24 x 24 (8.1, HOME). Also, 24 px at 2u per pixel would be 96 dp, too big for `HomeTile` (icon 26 dp, `HomeParts.kt:121`); HOME draws 48 dp.
5. Plan 7.1 gives ART-WORLD "fire.pxl, tab icon frames, the new glyphs of the pixel font": the lead moved the last two to 1b, and FIRE needs nothing from `fire.pxl`, so it stays byte-identical.
6. The day look rests entirely on SCENE's tint table: the art is drawn at night. If the first day pictures look dull (the meadow's four dark greens are close in value), the fix is the table or, last resort, a day palette per family; no sprite is redrawn. The taste gate for the default sky is judged on these pictures.
7. The moon frames are the northern view; the southern flip is SCENE's (request 6). Moon dates in section 8 are mean-phase values: SCENE's reference table decides.
8. Sprites chosen by index look animated if drawn with `PixelImage(name)`; only `PixelStage.blit(sprite, frame, ...)` may draw `scene_moon_phases` and `scene_woodpile`.
9. `craft_art.py` uses `math.sin`; the README's platform note applies (round before a threshold); the new code avoids floats where it can.
10. The generated pictures are drawn from code without a compiler or an eye in the loop: tiles and empties are the weakest part and are cut individually, never as a group (cut order, section 1).
11. Cultural and regional days: no art in this half (the touches are points drawn by SCENE, as `drawDistantNewrozFires` at `SceneRenderer.kt:100`); the installation's Newroz bonfires stay SCENE's and keep working because the base sprites do not change.
